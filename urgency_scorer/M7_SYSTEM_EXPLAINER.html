What is M7?

M7 is a hybrid intelligence engine that decides which farmers to message, when, and through which channel — without spamming them.

It answers one question:

"Should we intervene with this farmer right now, and if so, how?"

It does NOT claim to predict crop danger from ML alone. Instead it combines:

🌿 Agronomic Intelligence

Rule-based urgency from pest risk, weather, and crop stage. Works instantly for any farmer.

📊 Behavioral ML

Predicts engagement likelihood from historical click/response data. Improves over time.

System Architecture (3 Layers)

Layer 1: Agronomic Rule Engine → urgency_score
↓
Layer 2: Behavioral ML Layer → engagement_score
↓
Layer 3: Delivery Intelligence → intervention_priority + channel + suppress

Why 3 layers?

Because urgency ≠ engagement. A farmer can be in critical danger (high urgency) but never open WhatsApp messages (low engagement). The system must know both to decide the right action — escalate to voice call instead of sending another ignored push notification.

Layer 1: Agronomic Urgency (Rule Engine)

This is the primary scoring layer. It is deterministic, explainable, and works instantly for any farmer — including brand new ones with zero history.

urgency = 0.40 × pest_risk + 0.30 × weather_anomaly + 0.20 × crop_vulnerability + 0.10 × (1 − recency_penalty)
Factor Weight Rationale
Pest Risk 40% Strongest urgency driver — active outbreaks need immediate intervention
Weather Anomaly 30% Time-sensitive — drought/frost windows close quickly
Crop Vulnerability 20% Critical growth stages (flowering, heading) amplify all risks
Communication Window 10% Bonus for farmers not recently contacted (reduces spam)

Example Calculation

pest_risk = 0.82 → 0.40 × 0.82 = 0.328
weather = 0.71 → 0.30 × 0.71 = 0.213
vulnerability = 0.66 → 0.20 × 0.66 = 0.132
recency_penalty = 0.20 → 0.10 × (1 − 0.20) = 0.080

urgency_score = 0.75

Recency Penalty

Exponential decay: penalty = e^(−days / half_life) where half_life ≈ 10 days. Messaged yesterday = penalty ~0.9. Messaged 30 days ago = penalty ~0.05.

Layer 2: Behavioral Engagement (ML + Cold-Start)

This layer answers: "Will this farmer actually respond if we message them?"

It is NOT predicting urgency. It predicts engagement propensity — the likelihood of a click/response.

For Known Farmers (have history)

XGBoost Classifier

Trained on clicked_status (~5% base rate). Uses real behavioral signals: district CTR, device type, farm size, recency, seasonality, product scan history, offline campaign attendance.

For New Farmers (cold-start)

Population Priors

No history? No problem. The system uses:

  • District average CTR — "Farmers in Nashik click at 8%"
  • Crop average response rate — "Wheat farmers respond at 5.3%"
  • Device-level engagement — "Smartphone users engage at 7%"

Blended: 0.50×district + 0.30×crop + 0.20×device

Confidence-Aware Weighting

The system knows when to trust ML and when not to:

Scenario Confidence Effective Engagement Weight
Known farmer + ML model 1.0 0.30 (full weight)
New farmer + population priors 0.5 0.15 (half weight)
No model available (heuristic) 0.3 0.09 (minimal weight)

Key insight: When confidence is low, the system leans almost entirely on agronomic urgency. ML never distorts priorities when it can't be trusted.

Layer 3: Delivery Intelligence

Combines urgency + engagement into a final intervention decision.

intervention_priority = (1 − eng_weight) × urgency + eng_weight × engagement
where eng_weight = 0.30 × confidence

Channel Recommendation Matrix

Urgency Engagement Device → Channel
HIGH ≥0.7 LOW <0.3 Keypad 🚜 Field Visit No Action (Wait) No Action (Wait)

Fatigue Suppression Guard

Prevents message spam

Hard suppress Messaged ≤3 days ago → ALWAYS suppress (regardless of urgency)
Soft suppress Messaged ≤7 days ago AND intervention_priority < 0.45 → suppress
Critical override High priority bypasses soft guard (urgent messages still get through)

Why this works

  • Cold start works immediately — no dependence on historical labels
  • ML improves over time as farmer history accumulates
  • System degrades gracefully — never breaks for edge cases
  • Rural sparse-data districts still get scored correctly

Methodology

  • Urgency weights: LogisticRegression on clicked_status | product_scan → normalized absolute coefficients
  • Engagement model: XGBoost + CalibratedClassifierCV (isotonic) on clicked_status only
  • Split strategy: Temporal — train Oct 2025–Feb 2026, test Mar–Apr 2026
  • No synthetic features: All signals derived from real POS, campaign, and grower data
  • Cold-start: Population priors from district/crop/device CTR aggregates

Honest Limitations

  • Key distinction: The learned coefficients optimize intervention responsiveness, not biological risk causality. Communication_window dominates because recently-messaged farmers engage less — this is behaviorally true but does not mean timing equals pest severity.
  • Agronomic features (pest_risk, weather) are proxied from POS demand patterns, not real sensors
  • Weather_anomaly weight (0.07) likely reflects missing real weather data, not low importance
  • Small temporal test set (306 samples) limits statistical power
  • System improves as real agronomic APIs (weather, satellite NDVI, district outbreak history) become available

Intervention Economics

The system doesn't just route — it optimizes expected intervention value:

expected_value = (success_probability × benefit) − channel_cost
Channel Relative Cost When Used
📱 WhatsApp 0.05 Default for smartphone users with moderate+ engagement
💬 SMS 0.10 Keypad users, moderate urgency
📞 Voice Call 0.50 High urgency + low digital engagement
🚜 Field Visit 1.00 Critical urgency + unreachable digitally
⏸️ Suppress 0.00 Fatigue guard fires — no intervention

This reframes the system from "routing logic" to "decision optimization" — choosing the intervention with the highest expected ROI.
